# Demo and acceptance checklist

These checks are planned; none have run on an application yet.

## Main teaching flow

- [ ] Supply a short reviewed source and choose a tested teaching language.
- [ ] The teacher starts explaining without repeated student prompts.
- [ ] Board content matches the spoken section.
- [ ] A question checkpoint waits for the learner.
- [ ] Correct reasoning, incorrect reasoning and unclear transcription get different handling.
- [ ] The fractions misconception receives a changed explanation and a new transfer question.
- [ ] Pause stops current audio. Ask a doubt, receive an answer, and resume the correct step.
- [ ] An old response cannot play after pause/resume or a newer answer.
- [ ] Source/page references point to actual supplied material.
- [ ] Missing credentials, source parsing errors and speech failures have visible recovery states.

## Optional teammate feature

- [ ] Upload a permitted reference recording and confirm voice-use rights.
- [ ] Creation returns a selectable profile or a clear failure.
- [ ] Preview plays the actual custom voice output.
- [ ] Selecting a custom voice changes future teacher speech without losing lesson state.
- [ ] Preset speech works if custom voice is unavailable.
- [ ] Fallback voice is labeled accurately.
- [ ] Reference files, generated audio and credentials are excluded from commits.

## Three-minute story

1. Introduce the learner's source and the goal.
2. Let the teacher explain using the board.
3. Give the deliberate wrong reason and show the targeted repair.
4. Ask a doubt and demonstrate resumption.
5. If ready, preview/select the uploaded voice and play one new teaching section.
6. Show the application question and explain the Sarvam components actually used.

Use live behavior where verified. Label mocks and recordings as such. Report observed results, not invented mastery or improvement percentages. Rehearse on the actual browser before adding optional features.
